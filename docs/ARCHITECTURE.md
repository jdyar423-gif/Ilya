# Ilya 架构说明

```
                ┌──────────── 共享上下文流（与问题无关，每个上下文只算一次）────────────┐
 context ─► tok + RoPE ─► prelude ─► LN ─► c_e ──► [ctx_core]×T  (权重共享的双向块，循环，每步注入 c_e)
                                                   │ c_1 … c_T
                                                   ▼  只读 cross-attention（仅问题槽与答案槽）
 question m ─► [instr tokens ; ANS/NONE ; cand_1 … cand_K] ─► [ws_core]×T（同样循环，每步注入 w_e）
                                   │                                   │
     cand_k = e_k + MLP(e_k)，e_k = mean tok(rubric_k 或 name_k)        ├─ 第 t 步读出:
     （无位置编码 → 集合；有 rubric 时 name 不进入模型）                  │   s_NONE = f(ANS)
                                                                       │   s_k = ⟨W·ANS, e_k⟩ + bilinear(ANS, cand_k) + g(cand_k)
                                                                       └─ 置信度 ≥ τ 时该问题停机（anytime），全部停机即提前结束
```

| 组件 | 作用 | 针对的 Jev 弱点 |
|---|---|---|
| 隔离的问题工作区 | 问题之间互不注意，答案不随同批问题变化；上下文只编码一次，所有问题共享 | W4（请求配置翻转）；保留"一次编码、多次决策"的效率 |
| **问题驱动的证据检索** | 只有问题槽和答案槽读取上下文；候选只是假设，由证据来打分，自己不去上下文里"找自己" | 选项诱导的确认偏差（见下文"关键发现"） |
| 候选即集合 | 候选 token 无位置编码，读出逐候选进行 → 对选项顺序**精确**等变 | W3（顺序可造成 13 个百分点变动） |
| rubric 权威绑定 | 选项语义 = rubric；名称只是返回给调用方的标识符，有 rubric 时名称根本不进入模型 | W3（名称–rubric 互换后 AUROC .81→.58） |
| 隐式 NONE 结果 | 每个问题都有与候选竞争的 NONE 槽（choice / score / noul 全部适用），并用越界样本训练 | W1（没有"以上都不是"选项时 30 条越界 0 条被标出） |
| 循环 anytime 核心 | 权重共享的块循环 T 次；每一步都用严格恰当评分规则监督 → 每步信念都是"给定目前计算量"的校准后验；推理时逐题按置信度停机，可以跑得比训练时更久 | W5（固定算力，无法深想） |
| 条件化一致性层 | 把调用方声明的逻辑约束作为证据，对隔离信念的乘积做**精确**条件化，返回一致的边缘分布、满足全部约束的联合 MAP，以及"支持度" P(C)（自相矛盾警报） | W4（个体判决不一致） |
| 统计保证层 | 温度缩放；Learn-then-Test 认证门限（以 ≥1−δ 概率保证选择性风险 ≤ ε）；分裂共形预测集；带"升级"动作的代价敏感决策 | W2（置信度不是契约） |

## 训练目标

对每次迭代 t 的读出都施加交叉熵（严格恰当评分规则），权重随 t 线性增加：

L = Σ_t w_t · CE(softmax([s_NONE, s_1..s_K])_t, y)，w_t ∝ t

y = 0 表示 NONE（越界 / 以上皆非）。这与 RLCD 的目标一致（奖励 = 所报概率与实际正确频率的匹配），只是直接用恰当评分规则做监督学习：在有标签时两者最优解相同，而监督学习的方差更小。

## 关键发现：检索必须由问题驱动

第一版中候选 token 也会 cross-attend 上下文。在保留集上，Ilya 对"可回答"的颜色问题卡在 66%，
而"选上下文里出现过的那个颜色"这一捷径的期望准确率是 61%，说明模型几乎没有把颜色绑定到主语上。
检查学到的恒等偏置发现：候选头学会了"同符号"通道（β≈1.5–1.9），也就是**选项在上下文里找自己**；
而 Jev 复刻版只用"归纳"通道（主语 → 其后的属性词）。把上下文读取限制在问题槽和答案槽之后，
同样 1000 步内可回答准确率从 66% 升到 91.5%，学到的偏置变为：归纳通道 +5、同符号通道 −2。

这不只是训练技巧：让选项自己搜索证据，本质上就是让答案候选"引导"证据检索（确认偏差），
这正是依赖选项名的系统（如 Jev）会被误导名称带偏的原因之一。

## 与 Jev 复刻版的公平性

- 同一个数据生成器、同样的批大小、优化器、学习率计划、训练步数；参数量接近（Ilya 86.7 万，复刻版 81.3 万）。
- 两个家族获得**完全相同**的检索先验：RoPE 位置编码 + 恒等感知注意力（同符号通道与归纳通道，每个头可学习的标量，初始化为 0）。
  这相当于预训练 LLM 已具备的检索电路；本环境无法下载预训练权重（Hugging Face 被网络策略拦截，且只有 CPU）。
- 复刻版采用所有公开 Jev 式实现共同的机制：因果 LM、共享前缀 KV cache、问题作为隔离后缀、在答案位读取选项 token 的 logits
  （默认读取选项名 token，即 jev-visual 的 "native token" 读出；也支持 simple-jev 的字母标签读出 `--readout label`）。
- 两个 Jev 变体：`jev`（封闭世界，只在界内数据上训练，它无法表达 NONE）与 `jev_none`（始终附加显式 "none of these" 选项，
  与 Ilya 使用相同的越界训练数据；这比真实 Jev 更强，因为真实 Jev 的 score / noul 题型无法附加选项）。
- 所有模型在各自的校准集上做温度缩放后再计算任何指标。
